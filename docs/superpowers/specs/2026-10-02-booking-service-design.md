# pa_booking_service — дизайн

Дата: 2026-10-02. Статус: одобрена (2026-10-02, включая Д-8/Д-9).

## 1. Цель и рамки

Перенести из eXpress-ботов в Личный Кабинет две функции:

- **Записи** к психологу и на консультацию МКР (матрица карьерного роста);
- **Библиотеку** — бронирование книг.

**Критерий успеха:** сотрудник записывается и бронирует книгу в ЛК; специалист и
библиотекарь ведут слоты/каталог и выгрузки там же; боты `psy_bot_v2` и
`Library_bot` отключены.

**Исходные решения (согласованы):**

| # | Решение |
|---|---|
| Р-1 | Психолог и МКР — **один специалист, один календарь**; различается только тип записи |
| Р-2 | Пользователи **полностью** уходят из eXpress в ЛК; параллельной работы с ботами нет |
| Р-3 | Связки eXpress HUID ↔ пользователь ЛК **нет**; актуальные брони переносим вручную/скриптом |
| Р-4 | Бизнес-правила — **как в проде ботов**, с явными расхождениями из §4.3 |
| Р-5 | Уведомления специалистам — **в служебные чаты eXpress через BotX** (только исходящие); пользователь узнаёт об отмене специалистом **в ЛК** (статус записи) |
| Р-6 | Один сервис `pa_booking_service` с двумя изолированными модулями (не два сервиса, не домен в BFF) |
| Р-7 | Записи не стираются при удалении слота специалистом — получают статус `cancelled_by_specialist` |

**Вне рамок:** перенос истории прошлых записей/выдач; уведомления пользователям вне
ЛК (email, eXpress); лимит на число книг; ограничение числа продлений.

## 2. Источники и что откуда взято

Проанализированы: `projects/psy_bot_v2`, `projects/Library_bot` (прод-боты) и
`projects/eliseev/{psy,mkr,library}-220926` (черновые FastAPI-CRUD).

| Источник | Что берём | Что не берём и почему |
|---|---|---|
| `psy_bot_v2` | Все правила записей: лимит 4/месяц, замок 14:00 МСК, жёсткое удаление при поздней отмене, ежедневная чистка, тексты уведомлений, выгрузки | Даты строками `DD.MM.YYYY`, `ALTER` при старте, соединение на запрос, тип записи свободным текстом |
| `Library_bot` | Модель «книга + история выдач», бронь на 7 дней, продление +7, жанры, уведомления, выгрузка истории | Связь истории с книгой по `title`; `rowcount` от INSERT в истории вместо UPDATE книги (`database.py:166-180`) |
| eliseev | Идеи ресурсов: отдельные `extend`/`return`, админские списки «активные/просроченные» | Код целиком: нет аутентификации, пользователь из `?email=`, сломан поток psy/mkr (`fio` пишется ФИО, ищется по email), другие таблицы, иные правила (3 активные, 3 часа), в psy нет `main.py` |

## 3. Архитектура

```
SPA ──Bearer──> pa_bff ──X-API-Key + X-User-Id/Roles──> pa_booking_service ──> PostgreSQL
                 /api/appointments/* → /appointments/*          │
                 /api/library/*      → /library/*               ├─ Celery beat: 14:00 МСК чистка
                                                                ├─ ростер из pa_auth (ФИО)
                                                                └─ BotX → служебные чаты eXpress
```

Раскладка пакета `src/pa_booking/` по образцу `pa_overtimes`:

| Модуль | Назначение |
|---|---|
| `domain/appointments.py` | Чистые правила записей. Вход/выход — dataclass'ы, `now` параметром |
| `domain/library.py` | Чистые правила библиотеки |
| `domain/roles.py` | `Role(StrEnum)`: `psychologist`, `librarian`; разбор `X-User-Roles`; `admin` другие роли **не** покрывает |
| `db/` | Модели SQLAlchemy, Alembic |
| `api/appointments.py`, `api/library.py` | Роутеры; друг друга не импортируют |
| `core/` | Настройки (`PA_BOOKING_`), M2M-auth, логи, метрики |
| `directory/` | Синк ростера `GET /v1/directory/roster` → локальная таблица ФИО (копия механики `pa_overtimes/directory`) |
| `notify/botx.py` | `Protocol Notifier` + BotX-реализация + `FakeNotifier`. Отправка без ожидания колбэка |
| `export/xlsx.py` | Выгрузки (`openpyxl`), общие для обоих модулей |
| `workers/` | Celery + RedBeat: чистка 14:00 МСК, синк ростера |

**Сеть:** без host-порта, только `pa_net`, алиас `booking-api`.

**BotX.** Используем существующие аккаунты ботов: аккаунт `psy_bot_v2` шлёт в чат
специалиста, аккаунт `Library_bot` — в чат библиотеки. После отключения ботов их
вебхуки не нужны — аккаунты только отправляют. Настройки на модуль:
`PA_BOOKING_APPOINTMENTS_BOT_ID`, `..._BOT_SECRET`, `..._NOTIFY_CHAT_ID` и
аналогичные `PA_BOOKING_LIBRARY_*`, плюс общий `PA_BOOKING_BOTX_CTS_URL`.

Отправка (решение 2026-10-03) — без pybotx: синхронный `POST
/api/v4/botx/notifications/direct/sync` с JWT бота, как в сервисе `express_notif`.
JWT (HS256, формат как `pybotx.auth.build_botx_jwt_v2`) подписываем через **`pyjwt`**.
Проверено 2026-10-06: сообщения от обоих ботов доходят в служебные чаты
(`tests/external/test_botx.py`). Прежние `HTTP 204` без доставки — следствие битой
строки в `.env` (непарная кавычка), а не поведение BotX.

## 4. Модель данных и правила

Все «сегодня», 14:00 и границы месяца — по `Europe/Moscow`.

### 4.1. Записи

```
appointment_slots
  id            bigint PK
  slot_date     date        NOT NULL
  slot_time     time        NOT NULL
  created_at    timestamptz NOT NULL
  removed_at    timestamptz NULL
  UNIQUE (slot_date, slot_time) WHERE removed_at IS NULL

appointment_bookings
  id            bigint PK
  slot_id       bigint FK → appointment_slots NOT NULL
  employee_id   uuid        NOT NULL
  kind          enum(psy, mkr) NOT NULL
  status        enum(active, cancelled_by_user, cancelled_by_specialist) NOT NULL
  created_at    timestamptz NOT NULL
  cancelled_at  timestamptz NULL
  UNIQUE (slot_id) WHERE status = 'active'
```

Слот удаляется мягко (`removed_at`) — история остаётся для выгрузок. Уникальность
активной брони на слот — защита от гонки: второй одновременный INSERT → 409.

| Действие | Правило |
|---|---|
| Свободный слот | `removed_at IS NULL`, нет активной брони, начало слота > `now` |
| Записаться | Слот свободен; у пользователя **< 4 активных** броней со `slot_date` в месяце даты выбранного слота (прошедшие активные считаются, отменённые — нет) |
| Отмена пользователем | Только своей активной брони и только пока начало слота > `now`. Если `slot_date` = сегодня и `now` ≥ 14:00 — бронь `cancelled_by_user` **и** слот `removed_at = now`; иначе бронь `cancelled_by_user`, слот снова свободен |
| Чистка 14:00 МСК (beat) | Свободные слоты на сегодня → `removed_at`; если удалено ≥ 1 — уведомление в чат. При старте воркера после 14:00 — однократный догоняющий прогон (как в боте) |
| Специалист добавляет слоты | Пачкой `{date, times[]}`; дата не раньше сегодня (Д-8); дубли пропускаются → ответ `{added, duplicates}`. Слот на сегодня после 14:00 **разрешён** (как в боте) |
| Специалист удаляет слот | Свободный → `removed_at`. Занятый и ещё не начавшийся → `removed_at` + бронь `cancelled_by_specialist` + уведомление в чат. Занятый и уже начавшийся → 409 `slot_in_past` (Д-9) |
| Мои записи | Брони с началом слота ≥ `now` в статусах `active` и `cancelled_by_specialist` |
| Обзор специалиста | Слоты месяца ±3 дня соседних (как в боте) с бронями, ФИО и типом |
| Выгрузки xlsx | За месяц и за всё время: дата, время, ФИО, тип, статус |

### 4.2. Библиотека

```
library_books
  id            bigint PK
  genre         varchar(255) NOT NULL
  author        varchar(255) NOT NULL
  title         varchar(255) NOT NULL
  description   text         NOT NULL
  created_at    timestamptz  NOT NULL
  removed_at    timestamptz  NULL

library_loans
  id            bigint PK
  book_id       bigint FK → library_books NOT NULL
  employee_id   uuid   NOT NULL
  starts_on     date   NOT NULL
  due_on        date   NOT NULL
  returned_at   timestamptz NULL
  returned_by_librarian boolean NOT NULL DEFAULT false
  created_at    timestamptz NOT NULL
  UNIQUE (book_id) WHERE returned_at IS NULL
```

Выдачи — одновременно история (замена `all_reserv_book`).

| Действие | Правило |
|---|---|
| Каталог | Книги с `removed_at IS NULL`; признак «свободна» = нет невозвращённой выдачи |
| Забронировать | Книга свободна → `starts_on` = сегодня, `due_on` = сегодня + 7. Лимита нет |
| Продлить | Своя невозвращённая выдача, `due_on` ≥ сегодня → `due_on += 7`. Число продлений не ограничено |
| Вернуть (пользователь) | Своя невозвращённая выдача, в т.ч. просроченная |
| Вернуть (библиотекарь) | Любая невозвращённая выдача; `returned_by_librarian = true` |
| Каталог (библиотекарь) | Добавить, изменить — всегда; удалить (мягко) — только если книга не на руках |
| Мои выдачи | Невозвращённые, просроченные помечены |
| Выдачи (библиотекарь) | `active` (`due_on` ≥ сегодня) и `overdue` (`due_on` < сегодня) |
| Уведомления в чат | Бронь, продление, возврат (с пометкой, если отметил библиотекарь) |
| Выгрузка xlsx | История выдач: книга, ФИО, начало, срок, дата возврата, кто отметил |

### 4.3. Согласованные расхождения с ботами

| # | Было в боте | Стало |
|---|---|---|
| Д-1 | Тип записи — свободный текст-ответ на «психолог или МКР?» | `kind: psy \| mkr`, свободного комментария нет |
| Д-2 | Можно отменить запись на сегодня и после её времени | Отмена только до начала слота |
| Д-3 | Просроченная книга пропадала из «Моих броней» (`end >= CURDATE()`), вернуть было нельзя | Просроченные видны и возвращаются |
| Д-4 | Возврат только пользователем | Библиотекарь тоже может отметить возврат |
| Д-5 | Админы — `ADMIN_HUIDS` в env | Роли `psychologist` / `librarian` в `pa_auth_service` |
| Д-6 | Админ удаляет занятый слот → личное сообщение пользователю в eXpress | Статус `cancelled_by_specialist`, видно в ЛК |
| Д-7 | `ORDER_BOOK_LINK` в env бота | Ссылка «заказать книгу» — в конфиге SPA, сервис её не хранит |
| Д-8 | Выбор даты для добавления слотов включал 3 дня прошлого месяца — можно было создать слот в прошлом | Дата добавляемых слотов — не раньше сегодня (422) |
| Д-9 | Админ мог удалить любой слот в диапазоне, в т.ч. прошедший занятый | Прошедший занятый слот не удаляется (409 `slot_in_past`) — иначе состоявшаяся встреча пропала бы из выгрузки как «отменена специалистом» |

## 5. API

Пути сервиса — без `/api`; BFF зеркалит их под `/api/appointments/*` и
`/api/library/*`. Все запросы — с `X-API-Key`, `X-User-Id`, `X-User-Roles`.

### 5.1. Записи

| Метод | Путь | Роль | Описание |
|---|---|---|---|
| GET | `/appointments/slots?from=&to=` | любой | Свободные слоты, сгруппированные по дате |
| POST | `/appointments/bookings` `{slot_id, kind}` | любой | Записаться → 201 |
| GET | `/appointments/bookings/my` | любой | Мои будущие записи (§4.1) |
| POST | `/appointments/bookings/{id}/cancel` | владелец | Отмена |
| GET | `/appointments/admin/slots?month=YYYY-MM` | psychologist | Обзор месяца ±3 дня |
| POST | `/appointments/admin/slots` `{date, times[]}` | psychologist | Добавить слоты → `{added, duplicates}` |
| DELETE | `/appointments/admin/slots/{id}` | psychologist | Удалить слот |
| GET | `/appointments/admin/export?month=YYYY-MM` / `?all=true` | psychologist | xlsx |

### 5.2. Библиотека

| Метод | Путь | Роль | Описание |
|---|---|---|---|
| GET | `/library/genres` | любой | Список жанров |
| GET | `/library/books?genre=` | любой | Каталог с признаком «свободна» |
| POST | `/library/books/{id}/loan` | любой | Забронировать → 201 |
| GET | `/library/loans/my` | любой | Мои невозвращённые выдачи |
| POST | `/library/loans/{id}/extend` | владелец | Продлить |
| POST | `/library/loans/{id}/return` | владелец | Вернуть |
| POST | `/library/admin/books` | librarian | Добавить книгу |
| PATCH | `/library/admin/books/{id}` | librarian | Изменить |
| DELETE | `/library/admin/books/{id}` | librarian | Удалить (мягко) |
| GET | `/library/admin/loans?state=active\|overdue` | librarian | Выдачи |
| POST | `/library/admin/loans/{id}/return` | librarian | Отметить возврат |
| GET | `/library/admin/export` | librarian | xlsx истории |

### 5.3. Поток запроса (пример: запись)

1. BFF валидирует JWT по JWKS, зовёт сервис с M2M-ключом и контекстом пользователя.
2. Роутер разбирает роли, читает слот и число активных броней в месяце.
3. Доменная функция проверяет правила (§4.1) и возвращает решение или ошибку.
4. Одна транзакция: INSERT брони, COMMIT (уникальный индекс ловит гонку → 409).
5. **После коммита** — `notifier.send(...)` с ФИО из ростера.

### 5.4. Ошибки

Тело: `{"detail": "<по-русски>", "code": "<машинный>"}`.

| Код | Когда |
|---|---|
| 401 | Нет/неверный `X-API-Key` или нет `X-User-Id` |
| 403 | Нет нужной роли |
| 404 | Не найдено **или чужое** (существование чужого не раскрываем) |
| 409 | `slot_unavailable`, `monthly_limit`, `too_late_to_cancel`, `slot_in_past`, `book_unavailable`, `loan_overdue`, `book_on_loan` |
| 422 | Невалидный ввод (Pydantic) |

**Сбой BotX** не откатывает операцию: warning в лог + счётчик
`booking_notify_failures_total{module}`. **Ростер не синхронизирован** — в
уведомлении/выгрузке вместо ФИО `employee_id`.

### 5.5. Тексты уведомлений

Берутся из ботов с заменой username на ФИО:

- запись: `✅ {ФИО}\nЗаписался на {dd.mm.yyyy} в {hh:mm}\n{Психолог|Консультация МКР}`;
- отмена пользователем: `❌ {ФИО}\nОтменил запись на … в …\n{тип}`;
- удаление занятого слота: `Слот {дата} — {время} был удалён, запись {ФИО} отменена`;
- чистка: `Свободные окна на сегодня {hh:mm, …} были удалены`;
- библиотека: `{ФИО} забронировал книгу {title} ⏳\nДата возврата: …`, аналогично
  продление и возврат.

## 6. BFF и SPA

**pa_bff:** клиент `clients/booking.py` (`Protocol` + httpx + `Fake*`) по образцу
`clients/overtimes.py`; роутеры `api/appointments.py`, `api/library.py` —
проксирование 1-в-1, xlsx — потоком. Домена в BFF нет.

**SPA:** страницы `/appointments/*` и `/library/*` (конвенция неймспейсов).
Пункты меню — всем; вкладки специалиста/библиотекаря — по ролям. Ошибки — по
`code`, текст — из `detail`. Ссылка «заказать книгу» — из конфига SPA.

## 7. Перенос данных

Разовые скрипты `scripts/` из MySQL ботов. В таблицах ботов есть **только HUID**
(username не сохранялся).

**Автоматически (без пользователей):**

- каталог `Library_books` → `library_books` (без полей брони);
- будущие **свободные** слоты `record_psy_pari` (`user_huid IS NULL AND tg_id IS NULL`)
  → `appointment_slots`, строки `DD.MM.YYYY` / `HH:MM` → `date` / `time`.

**С ручным сопоставлением:**

1. Скрипт выгружает в CSV активные брони: будущие записи (`HUID, дата, время,
   комментарий`) и книги на руках (`HUID, book_id, title, start, end`).
2. Вы заполняете колонку `employee_id` (HUID → ФИО — таблица `express_user_mentions`
   в БД `express_notif` или BotX `GET /api/v3/botx/users/users_as_csv`; ФИО →
   `employee_id` — директория ЛК).
3. Скрипт импортирует CSV; строки без `employee_id` пропускаются с отчётом. Тип
   записи из свободного комментария не выводится автоматически — колонка `kind`
   заполняется вручную.

Если активных броней немного — проще завести их руками через админку ЛК, шаги 1–3
не нужны. Прошлую историю не переносим: она остаётся в MySQL (при нужде — выгрузка
ботовым Excel до отключения).

## 8. Тесты и выкатка

**Тесты:**

| Уровень | Что | Чем |
|---|---|---|
| Домен | Лимит 4/месяц (граница месяца, прошедшие считаются, отменённые — нет); 14:00 МСК (13:59 vs 14:00); отмена до/после начала; сроки и продление; просрочка | pytest, `now` явно |
| API | Роли (403), чужое (404), гонка за слот (409), уведомление только после коммита | `db` (testcontainers Postgres) + `FakeNotifier` |
| Чистка | Удаляет только свободные слоты на сегодня; без удалённых — без уведомления | `db` |
| BotX | Отправка ботом без вебхуков | `external` |
| BFF | Проксирование путей, заголовков, потоковый xlsx | `Fake*`-клиенты |
| SPA | Страницы, гейты по ролям, ошибки по `code` | vitest |

**Порядок выкатки:**

0. **Спайк BotX:** отправка сообщения из аккаунта бота без принятия вебхуков. Если
   не работает — пересматриваем Р-5 до написания остального кода.
1. Сервис + миграции, деплой в `pa_net`.
2. Роли `psychologist` и `librarian` в `pa_auth_service`, назначить людям.
3. BFF + SPA.
4. Импорт каталога и слотов; сопоставление/заведение активных броней.
5. Объявление пользователям.
6. Остановка ботов; их MySQL остаётся только на чтение до подтверждения переноса.

**Декомпозиция на планы:** шаг 0 → каркас сервиса → модуль записей → модуль
библиотеки → BFF+SPA → скрипты переноса. Каждый — отдельный блок плана реализации.
